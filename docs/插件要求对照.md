# 九类插件：要求 → 实现 → 证据（自己核对版）

用户的要求是这几条：

> 插件要有：基础工具插件（极简模式的）；进阶工具插件（标准模式的）；四个技能插件；
> 子智能体插件（设置递归层级、数量和模型）；终端插件（限制每条命令最长跑多久、最多输出多少，
> 用户自定义）；agent 大循环逻辑也做成插件（控制 Agent 派发工具调用的方式）；
> 智能体团队插件（agent 集群，用户自定义每个智能体用什么模式、干什么）；
> 自动授权审查插件（叫另一个模型对话审核）；自动化任务插件（按设定的时间或周期在会话中自动执行任务）。
> 插件都要可以热插拔，要有一个模式可以让用户自己开发插件，用户要能通过设置自己选择插件是否开启。

## 这次自己核对时**补掉**的四个真缺口

1. **参数不能自定义 = 要求没做到**：终端/大循环/子智能体/审查这些参数原来**只有后端接口，
   界面上没有任何入口**，用户根本改不了。补了参数界面；**1.5.2 起并进「插件管理」**（每个插件的参数贴在它自己那一行下面，含团队增删、自动化任务增删）。
2. **"提供商"配了等于没配**：审查插件读了 `model` 却没用 `provider`，永远拿主 Agent 的适配器去问 ——
   那不是"叫另一个模型"。现在按 provider 取对应适配器，取不到才退回当前适配器。
3. **"控制派发方式"缺最直接的一项**：一轮派几个工具此前是写死的（且不生效的 `capToolsPerRound`
   是死代码）。现在 `maxToolsPerRound` 可配：0 = 不限（保持用户要求的"给多少执行多少"），
   设了正数就按上限执行，**超出的调用按原顺序回一条"未执行、下一轮继续"**，不让模型以为干完了。
4. **"一类插件"没有组级开关**：想只留极简能用的那批，得点 22 次。加了
   `POST /api/plugins/kind/{kind}/enable|disable` + 每组的"全开/全关"按钮。

## ⚠️ 说清楚这三处"形态不一样"，别当成完全按字面做到

- **"基础工具插件 / 进阶工具插件"不是两个大插件，而是每个工具各自是一个插件、按模式自动归类。**
  好处是能精确到单个工具开关（比如只关 `web_search`）；代价是没有一个"基础工具集"的整体对象。
  组级开关（全开/全关）就是为此补的。
- **子智能体和智能体团队是"工具 + 插件配置"的组合**，不是两个独立的执行引擎：
  派活走的是主循环自己的工具调用链路（串行、可停、可审计），插件负责边界和配置。
  好处是"当前有几个子智能体在跑""哪个会话在干什么"始终说得清；代价是不能真并发跑多个子智能体
  （本机 llama-server 单 slot，并发也只是排队）。
- **自动化任务最小周期 5 秒、轮询间隔 15 秒**：它是"到点往会话里丢一条消息"，不是 cron 守护进程。
  秒级精确触发做不到（也不需要）。
