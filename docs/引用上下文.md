# 对话中的 @ 引用（@file / @history / @skill）

## 一句话

消息里写 `@file:路径`、`@history:会话`、`@skill:技能id`，服务端在**发给模型之前**把它们展开成真实上下文；
前端靠 `GET /api/context/mentions` 做补全，选中候选后把返回的 `insert` 原样插进输入框即可。

## 语法

| 写法 | 展开成什么 | 例子 |
| --- | --- | --- |
| `@file:<路径>` | 文件内容（≤200 行 / 20KB） | `@file:src/main/java/com/lioncode/LionCodeApplication.java` |
| `@file:<目录>` | 目录列表（≤100 项，带 `[DIR]`/`[FILE]`） | `@file:src/main/java/com/lioncode/core` |
| `@history:<会话id>` | 那个会话最近的 ≤30 条消息 | `@history:0f1e2d3c-...` |
| `@history:<关键词>` | 按标题/首条用户消息模糊匹配到某个会话，再展开 | `@history:技能系统` |
| `@skill:<技能id>` | 技能正文 | `@skill:backend` |
| `/skill:<技能id>` | 同上（命令写法） | `/skill:document` |

- 路径里**不能有空格**（一条引用以空白结束；末尾的中文标点和右括号会被自动去掉）。
- 原 token 会保留在消息里，展开内容紧跟其后，用 `--- 引用开始：… ---` / `--- 引用结束：… ---` 包起来。
- 同一个引用写两遍只展开一次（第二处标注"上面已经展开过"）。
- 代码块里的 `@file:` 也会被展开（没有做"跳过代码块"的处理，行为可预测优先）。

## 上限与安全

| 项 | 上限 | 超出时的行为 |
| --- | --- | --- |
| 单个文件 | 200 行 / 20KB / 读盘最多 512KB | 截断并在引用块头部标注"**已截断**，共 N 行" |
| 单个历史会话 | 30 条消息 / 20KB | 超出部分省略并标注 |
| 单个技能正文 | 40KB | 截断并标注 |
| 一轮消息的所有引用 | 80KB | 之后的引用不展开，给一句提示 |
| 路径范围 | 必须在工作区（或 `root` 参数）之内 | **拒绝读取**并说明"在工作区之外" |

- 引用失败（文件不存在、目录不可读、会话找不到、技能被禁用）**不会抛异常**，而是在原位插入
  `--- 引用失败：@file:xxx --- 原因：…`，用户和模型都能看到原因，消息照常发出去。
- 文件不存在时会附"同目录下相近的名字"，会话找不到时会列出可用的会话。
- 相对路径基于**会话绑定的工作区**解析；没有工作区时退到进程工作目录。

## 前端契约：`GET /api/context/mentions`

### 请求参数

| 参数 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `q` | 否 | `""` | 关键词；空字符串 = 返回默认候选（刚敲 `@` 时用） |
| `kind` | 否 | `all` | `file` / `history` / `skill` / `all` |
| `root` | 否 | 会话工作区 | 文件检索的根目录（`kind=file/all` 时用） |
| `sessionId` | 否 | — | 用来定位会话工作区，并在历史候选里**排除当前会话** |
| `limit` | 否 | `20` | 每类返回条数，最大 50 |

### 响应

```json
{
  "ok": true,
  "success": true,
  "message": "操作成功",
  "items": [
    { "type": "file",    "id": "src/main/java/com/lioncode/web/controller/ChatController.java",
      "label": "ChatController.java",
      "detail": "src/main/java/com/lioncode/web/controller/ChatController.java · 12.3 KB",
      "insert": "@file:src/main/java/com/lioncode/web/controller/ChatController.java" },

    { "type": "history", "id": "0f1e2d3c-....",
      "label": "技能系统改造",
      "detail": "24 条消息 · 把技能改成通用 SKILL.md 格式",
      "insert": "@history:0f1e2d3c-...." },

    { "type": "skill",   "id": "backend",
      "label": "后端开发技能",
      "detail": "后端代码编写、调试、编译排错、接口设计、依赖处理等后端相关能力",
      "insert": "@skill:backend" }
  ],
  "q": "chat",
  "kind": "all",
  "root": "C:\\Users\\leo\\Desktop\\lion-code",
  "limit": 20,
  "truncated": false,
  "elapsedMs": 37,
  "scannedFiles": 812,
  "counts": { "file": 12, "history": 0, "skill": 0 },
  "data": { "ok": true, "items": [ "…同上…" ] }
}
```

要点：

- **`insert` 就是可以直接插进输入框的文本**，前端不要自己拼前缀（服务端展开器只认这个格式）。
- 顶层同时有 `items` 和 `data.items`、`ok` 和 `success`：按哪套老习惯写代码都能取到值。
- `type` 只有 `file` / `history` / `skill` 三种；前端按它区分图标和分组。
- `truncated=true` 或 `note` 非空时建议在候选列表底部显示 `note`（工作区太大、目录不存在等情况）。
- 文件候选**不会**包含 `node_modules`、`target`、`dist`、`build`、`.git`、`.idea`、`venv` 等目录里的内容；
  检索最多遍历 20000 个文件、深度 12 层、**2 秒硬上限**（超时返回已找到的部分，`truncated=true`）。

### 前端调用示例

```js
async function fetchMentions(q, kind, sessionId, root) {
  const url = '/api/context/mentions?q=' + encodeURIComponent(q || '')
    + '&kind=' + encodeURIComponent(kind || 'all')
    + '&sessionId=' + encodeURIComponent(sessionId || '')
    + '&root=' + encodeURIComponent(root || '');
  const res = await (await fetch(url)).json();
  return res.items || (res.data && res.data.items) || [];
}

// 用户选中某个候选：把 "@xxx" 换进输入框
function applyMention(input, item) {
  const caret = input.selectionStart;
  const before = input.value.slice(0, caret).replace(/@[^\s@]*$/, '');
  input.value = before + item.insert + ' ' + input.value.slice(caret);
}
```

建议：输入框里 `@` 触发（防抖 150~250ms），`@` 后跟 `history:` / `skill:` 时把 `kind` 传成对应的值；
键盘上下键选择、Enter/Tab 插入、Esc 关闭。

## 服务端展开发生在哪

`ChatController`（`POST /api/chat` 和 `POST /api/chat/stream` 两条路都过）：

1. 展开 → 2. 写一条展开事件 → 3. 入队/直接调 `AgentLoop.processMessage`。

因此：

- **事件流里存的是用户原话**（界面上显示的就是用户打出来的样子，不会糊一屏文件内容）；
- **对话历史里存的是展开后的内容**（模型后续轮次能看到上下文）；
- **会话标题用用户原话生成**（`@file:src/x.java` 当标题比几千字文件内容合适）。

### 展开事件（前端可单独渲染）

```
type     = TOOL_CALL_COMPLETE
data.toolName = "context_expand"
data.result   = "已展开 @file:hello.txt（文件 hello.txt（3/3 行））"
data.mentions = ["@file:hello.txt", "@skill:backend"]
summary       = "已展开引用: 已展开 @file:hello.txt（…）"
```

当前的极简界面会把它显示成一行 `✅ context_expand 完成`；前端想做得更好看，
可以按 `data.toolName === 'context_expand'` 特判，用 `data.result` 展示"已展开 xxx"。

## 不走的路径

- 流式接口（`/api/chat/stream`）同样会展开；
- 预热服务（`PrewarmService`）和提示词预览（`/api/runtime/prompt-preview`）**不经过** ChatController，
  不会展开 @ 引用（它们用的是假消息，也不需要）。

## 排错

| 现象 | 原因 |
| --- | --- |
| 消息发出去了，但模型好像没看到文件 | 看事件流里有没有 `context_expand`；有的话看 `data.result` 是不是"展开失败"（文件不存在/越界） |
| `@file:` 没反应 | token 拼错（必须是小写 `@file:`），或者路径里有空格（不支持） |
| `@history:` 找不到 | 用 `GET /api/context/mentions?kind=history&q=<关键词>` 看候选，直接插 id 最稳 |
| 提示"路径在工作区之外" | 引用的是工作区外的绝对路径或 `..` 跳出去 —— 这是故意拦的 |
