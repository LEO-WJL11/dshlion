# 插件开发（插件开发模式）

## 一句话

打开**插件开发模式**，一条请求生成一个**能编译、能加载**的最小插件工程；
改完代码跑一次 `build.ps1`，再 `POST /api/plugins/reload` 就生效 ——
不用改主程序、不用重启软件、不用碰 Maven。

## 1. 打开开发模式

两种方式，随便挑一种：

```powershell
# 启动参数（一次性）
java -jar lion-code-agent-harness-1.0.0-SNAPSHOT.jar --lionbox.plugin.dev-mode=true
```

```http
POST /api/plugins/dev-mode
{"enabled": true}
```

运行时开关会**持久化**（写进 `<插件目录>/settings.json` 的 `devMode`），
下次启动按上次的选择来 —— 否则用户会觉得"这个开关关不掉"。

查状态：

```http
GET /api/plugins/dev-mode
→ {"ok":true,"devMode":true,"pluginsDir":"C:/Users/你/.lioncode/plugins",
   "devDir":"C:/Users/你/.lioncode/plugins/dev", ...}
```

开发模式没开时 `scaffold` 会**拒绝生成**（不会偷偷往磁盘写东西）。

## 2. 生成工程

```http
POST /api/plugins/scaffold
{"id": "demo.echo", "name": "回声示例", "kind": "BASE_TOOL"}
```

`kind` 可以是 9 类里的任意一类（也认中文显示名）：

| kind | 生成什么骨架 |
| --- | --- |
| `BASE_TOOL` / `ADVANCED_TOOL` | 工具插件（`AbstractToolPlugin`，含参数 schema 与 execute） |
| `SKILL` | 技能插件（`SkillPlugin`，往提示词注入片段） |
| 其余 6 类 | 系统插件骨架（`Plugin`，含 `isEnabledByDefault` 示例） |

生成的目录（在 `<插件目录>/dev/<id>/`）：

```
demo.echo/
  src/main/java/lionbox/plugins/demo_echo/DemoEchoTool.java   ← 插件本体（改这里）
  src/main/resources/META-INF/lionbox-plugin.properties       ← 声明哪个类是插件
  build.ps1                                                   ← 一键编译 + 打包 + 放进插件目录
  README.md                                                   ← 这个工程怎么用（生成的说明更具体）
```

`id` 会当目录名用，所以只允许字母、数字、点、下划线、短横线（挡住 `..` 和路径分隔符）；
目录已存在且不为空时**拒绝覆盖**（用户可能已经改了半天代码）。

## 3. 编译 & 加载

```powershell
cd <插件目录>\dev\demo.echo
powershell -ExecutionPolicy Bypass -File build.ps1
```

脚本做的事：找 `javac` → 编译 `src/main/java` → 把 class 与 `META-INF` 打进
`<插件目录>/<id>.jar` → 提示你调 reload。

> **需要 JDK 17+**（要的是 `javac`，不是只跑得起来的 JRE）。
> 没装 JDK 的话：装一个，或用 `-Javac <javac路径>` 指过去。

不想用脚本也行，等价的手工命令：

```powershell
$sdk = "<插件目录>\sdk\lionbox-plugin-api.jar"
javac -encoding UTF-8 -nowarn -cp $sdk -d build\classes (Get-ChildItem src\main\java -Recurse -Filter *.java).FullName
Copy-Item src\main\resources\* build\classes -Recurse -Force
jar --create --file ..\..\demo.echo.jar -C build\classes .
```

然后让它生效：

```http
POST /api/plugins/reload
→ {"ok":true,"count":1,"total":74,"errors":[],"plugins":[...]}
```

到「设置 → 插件」里就能看到 `demo.echo`（`source: external`、`hotReloadable: true`），
模型下一轮就能调用它。

### SDK jar 是什么

编译插件必须能 `import com.lioncode.core.plugin.Plugin`。但软件是 fat jar 启动的，
接口类都在 `BOOT-INF/classes/` 里，`javac -cp lion-code-agent-harness.jar` **找不到**它们
（javac 不会钻进 fat jar 的嵌套目录）。所以开发模式会把 `com/lioncode/**` 抽出来，
导出成 `<插件目录>/sdk/lionbox-plugin-api.jar` 供编译使用。

丢了就重新导一次：

```http
POST /api/plugins/sdk
→ {"ok":true,"path":".../sdk/lionbox-plugin-api.jar"}
```

## 4. 插件是怎么被找到的

加载器扫描**插件目录第一层**的 `*.jar`（`dev/` 下面的不会被扫，避免加载半成品），
然后按三种方式找"哪个类是插件"，取并集：

| 方式 | 写法 | 说明 |
| --- | --- | --- |
| 清单文件（推荐） | `META-INF/lionbox-plugin.properties` 里 `plugin.class=包名.类名` | 一行一个，也可以用 `plugin.classes=` / `plugins=`，逗号或空格分隔 |
| ServiceLoader 约定 | `META-INF/services/com.lioncode.core.plugin.Plugin` | 内容是实现类名 |
| 扫 class（兜底） | 什么都不写 | 兼容老插件包；会把 jar 里所有 class 撸一遍，最慢 |

每个 jar 用**独立的 `URLClassLoader`** 加载（父加载器是主程序），
这是"改了重新 build → reload 就拿到新版本"的前提：同一个 ClassLoader 加载过的类收不回来，
只有连 ClassLoader 一起丢掉，那个 jar 才算真的从进程里消失。

## 5. 三类骨架分别要注意什么

### 工具插件（BASE_TOOL / ADVANCED_TOOL）

| 方法 | 要点 |
| --- | --- |
| `getId()` | 插件唯一 id（设置开关、日志、卸载都认它），**全库唯一**，重了会被跳过并记一条"ID冲突" |
| `getName()` | 工具名，模型就是按这个名字调用；别和内置工具重名 |
| `getDescription()` | 写清"什么时候该用它"，模型靠它挑工具 |
| `getParametersSchema()` | JSON Schema；`required` 里的参数模型必须给 |
| `execute()` | 成功 `success(...)`、失败 `error(...)`；错误信息要写成"能照着改"的话，别只写"失败了" |
| `isAvailableInMode(mode)` | **决定它算基础工具还是进阶工具**：极简模式也能用 = 基础工具 |

参数一律用 `getStringArg` / `getIntArg` / `getBoolArg` / `getRequiredStringArg` 取：
文本通道（本地模型默认）下模型给的所有参数都是**字符串**，直接强转会
`ClassCastException`，这几个方法就是为这个存在的。

### 技能插件（SKILL）

技能不提供动作，它提供"规矩"：`getSystemPromptFragment()` 返回的文字会进系统提示词。

- **写短**：每一轮请求都会带上，几百字等于每轮多烧几百 token；
- 只写"模型不知道、又必须知道"的领域经验；
- `getRequiredToolIds()` 只是展示，工具开关各自独立。

### 系统插件（其余 6 类）

不提供工具，而是"改变别的插件怎么跑"。要让插件插进 Agent 主循环，
让它**同时实现** `com.lioncode.core.agent.spi.AgentSpi`：加载器发现后会自动注册，卸载时自动摘掉。

| 扩展点 | 作用 |
| --- | --- |
| `filterToolNames(sessionId, all)` | 决定这一轮下发给模型的工具清单 |
| `extraSystemSections(...)` | 往系统提示词追加段落 |
| `transformUserMessage(...)` | 改写信用户消息（例如展开 @ 引用） |
| `loopOptions(sessionId)` | 覆盖主循环参数：`maxIterations` / `toolTimeoutSeconds` / `silentRounds` |

返回值别乱给：`loopOptions` 只认上面三个 key，别的会被丢掉（防止插件把主循环搞坏）。
扩展方法抛异常只会记一条日志然后跳过，不会把主循环带崩 —— 但也意味着
**你的 bug 会静默失效**，写完记得看日志。

## 6. 生命周期与热插拔的注意事项

- **`initialize()` / `destroy()` 成对写**：在 `initialize` 里开的线程、端口、监听，
  必须在 `destroy` 里关掉。ClassLoader 关掉**不会**自动帮你收拾这些。
- **不要跨插件强转**：每个插件是独立 ClassLoader，A 插件 `new` B 插件的类会得到
  `ClassCastException`（同名不同加载器 = 不同类型）。要通信就用事件总线、或者把结果回给模型。
- **静态状态是陷阱**：静态字段跟着 ClassLoader 走，reload 之后是**新的一份**，
  别把状态存在静态变量里指望它跨 reload 保留（要持久化就用 `<插件目录>/settings.json` 那一套，或自己的文件）。
- **依赖尽量用主程序已有的**（Spring、Jackson、commons-*）：父加载器能提供，
  不必打进插件 jar。**不要**把 Spring Boot 整个打进去，那会让类加载关系变得没法预测。
- **卸载**：`DELETE /api/plugins/{id}` 会把插件从注册表、事件总线、AgentSpi 里摘干净，
  并 `close()` 掉它的 ClassLoader。内置插件（随软件自带的那些）卸载后要重启才能回来 ——
  `hotReloadable` 字段会如实告诉用户这一点。

## 7. 调试

| 想知道什么 | 看哪儿 |
| --- | --- |
| 插件有没有被加载 | `GET /api/plugins`，找你的 `id`；`source` 是 `external` 就是外置的 |
| 为什么没加载 | 同一个列表里 `broken: true` 的条目 + `error` 字段（坏 jar 也会出现在列表里） |
| 扫描/加载详细过程 | 应用日志，加载器会打 `插件 JAR 已加载: xxx.jar（1 个插件）` |
| reload 都发生了什么 | `POST /api/plugins/reload` 的 `errors` 数组 |
| 有哪些开发工程 | `GET /api/plugins/dev` |
| 插件现在开没开 | `GET /api/plugins` 里的 `enabled` |

## 8. 常见问题

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 列表里没有我的插件，也没有 `broken` 条目 | jar 不在插件目录**第一层**（`dev/` 下的不会被扫）；或 `META-INF/lionbox-plugin.properties` 里的类名写错了 |
| 列表里有一条 `jar:xxx.jar` 带红色错误 | 就是这个 jar 坏了，`error` 字段写了原因（类加载失败/ID 冲突/不是 zip） |
| 加载成功但模型看不到我的工具 | 插件被关了（设置里看 `enabled`）；或 `isAvailableInMode` 在当前模式下返回了 false |
| `build.ps1` 报 `Unexpected token ')'` | 脚本被当成 ANSI 读了。生成的脚本本身带 UTF-8 BOM，别用别的编辑器把它去掉 |
| `javac: 找不到符号 com.lioncode...` | `-cp` 没指到 SDK jar（`<插件目录>/sdk/lionbox-plugin-api.jar`） |
| reload 后还是老行为 | 改的是**别的** jar（比如 `dev/` 下那份）；reload 只重启外置 jar 的 ClassLoader，内置插件要重启软件 |
| 报 `ClassCastException` | 跨插件强转，见上面"不要跨插件强转" |

## 9. 想抄作业？

内置的 6 个系统插件就是最好的参考，它们都在 `src/main/java/com/lioncode/core/plugin/`：

| 插件 | 文件 | 能学到什么 |
| --- | --- | --- |
| 终端 | `TerminalPlugin.java` | 怎么把自己的配置做成"用户可改"，并且每次现读（改了立刻生效） |
| Agent 大循环 | `AgentLoopPlugin.java` | 怎么用 `AgentSpi.loopOptions` 插进主循环 |
| 子智能体 | `team/SubAgentPlugin.java` | 怎么做"强制校验 + 给模型一句能照做的拒绝话术" |
| 智能体团队 | `team/AgentTeamPlugin.java` | 列表型配置的增删改查 + 注入提示词 |
| 自动授权审查 | `review/ApprovalReviewPlugin.java` | 给另一个模型写提示词、解析它的回答 |
| 自动化任务 | `automation/AutomationPlugin.java` | 怎么把"到点判定"写成纯函数，交给主循环驱动 |

自测套件：`python tools/checks/_check_plugin_system.py`（里面就用 scaffold 生成工程、
javac 编译、打成 jar、reload 加载、再卸载，走完了整条链路）。
