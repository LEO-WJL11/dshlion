### 6. 修掉一个会误导用户的「自定义 API」默认值（含老配置迁移）

发现：`%USERPROFILE%\.lioncode\app-config.json` 里 `lionbox-custom`（「自定义 API」实例）
的 `baseUrl` 竟然是**本地端点** `http://127.0.0.1:8788/v1`。原因是
`AppConfigStore` 生成这个实例时传的是"当前生效的 baseUrl"，而默认模式是本地，于是就把本地端点抄了进去。

危害：自定义模式下本地运行时**不启动**，用户切过去如果没改地址，请求必然连接失败，
而且很难反应过来是自己没填。

修法（`AppConfigStore.java`）：
1. 新配置：自定义实例改用**存档**（`customApi`）里的端点与模型来初始化；
2. 老配置：新增一次性修复 `repairCustomProviderPointingAtLocal()` —— 只要发现自定义实例
   指向已知本地端点，就换成存档里的值；存档为空就留空，让界面空着提示用户填。

**迁移实测**（拿真实的老配置跑的，改动前先备份了配置）：

```
providerMode       : local                      ← 未变，当前模式没被动过
active baseUrl     : http://127.0.0.1:8788/v1   ← 未变
local  inst baseUrl: http://127.0.0.1:8788/v1   ← 未变
custom inst baseUrl: https://api.xiaomimimo.com/v1   ← 由本地端点修正为存档里的真实端点
custom inst models : mimo-v2.6-flash                 ← 同步补回存档里的模型
```

### 9. 预热与工具调用接线核对（读代码确认，未触发实际推理）

### 11. 测试踩到的两个坑（都记下来，避免下次误判）

1. **`Start-Process java` 拿到的是 `javapath` 垫片进程号**，杀掉它**不会**杀掉真正的 JVM。
   我第一次验证兜底时就是这样：残留实例还占着 8080，于是我查到的其实是**上一个实例**的
   `resolvedModelPath`（指向 repo 的 dist），差点得出"兜底没生效"的错误结论。
   正确做法：查 `Get-NetTCPConnection -LocalPort 8080` 的 **OwningProcess** 跟启动的 PID 对不对，
   或者直接用真 JVM 的全路径 `C:\Program Files\Java\jdk-26.0.2.1\bin\java.exe` 启动。
2. **验证任何"当前进程状态"之前先确认端口归属**。端口上是谁，你查到的就是谁——这句话在
   本机同时可能存在多个实例时尤其重要（e2e 测试、手动启动、安装后启动都可能撞在一起）。

所以 `AppConfigStore` 加了一次性迁移 `migrateLegacyModelName()`：

- 只动**盒子自己的实例**（`lionbox-local`，或端点仍是本地端点的实例）；
- **自定义 API 实例里如果恰好也叫这个名字就一律不动** —— 那是用户自己填的配置；
- 生效中的 `model` / `openai.model` 在本地模式下本来就被默认值流程覆盖，顺带一致。
