## 2026-09-29 · 第 31 轮：编译和打包都用 16 线程 + 全量清缓存重编

用户两条要求：**“编译和打包都用16线程”**、
**“Java 26 代码改完后要重新编译整个项目（清空所有编译缓存）”**。

- 编译：`mvn -o -T 16 -DskipTests clean package`（`-T 16` 并行，`-o` 离线，
  **默认带 clean**）；清掉整个 target 后 202 个 class 全量重生成，实测 **~5 秒**。
- 打包：`LZMANumBlockThreads=16`。实测发现 **solid 压缩是单流的**，开着
  `SolidCompression=yes` 时多线程设置等于没用：
  ultra64+solid+16 线程 = 31.0 秒 / 72.19 MB；ultra64+关solid+16 线程 = **23.6 秒 / 73.96 MB**；
  lzma2/max+关solid+16 线程 = 22.2 秒 / 74.07 MB。取中间：保住 ultra64，多 1.8 MB 换 7.4 秒。
- 新增 `_build.ps1`：清 target 全量重编 → 复制 jar 到 dist → ISCC 出包，打印两步耗时与包的 sha256。

### 100. 顺带查出并修掉两件事

**① 测试假失败：运行时端口撞上用户自己的 llama-server。**
`_check_model_choice.py` 里那个测试 app 用默认运行时端口 8788，而**用户自己那台
LionBox 的 llama-server 正跑在 8788**。于是 `healthy()` 一探测就返回 true，`ensureRunning()`
直接返回，永远走不到“下载配置的那份”分支 —— 第二阶段全线失败。
不是功能 bug，是测试隔离没做干净：现在测试显式 `--lionbox.runtime.port=8790`。

**② 日志刷屏：兜底警告每次状态查询都打。**
进度条每 1.5 秒查一次 `/api/runtime/local`，`status()` 每次都调 `resolvesModel()`，
那条“配置的模型 X 不可用”就跟着刷（一轮测试几百行）。
现在同一对（配置的 / 实际用的）**只打一次**。

**③ 公开仓库的提交信息写错了版本。**
往 dshlion 推的脚本一直读一个手写的临时文件（`_commit_1114.txt`）当提交信息，
各版本的收尾脚本各自往里写 —— 1.2.7 那次忘了重新生成，于是推上去的
提交信息还是 1.2.6（内容是对的、信息是错的）。现在 `_push_dshlion.sh` 改成
**自动取 `git log -1 master` 的原文**，并在开头写上版本号 —— 不再依赖任何手写临时文件。

## 2026-09-29 · 第 34 轮：搜索走无头浏览器 + 修好实测坏掉的工具

### 107. 网络搜索：从占位实现到无头浏览器

原来那个 `web_search` 根本不能用（只回一句“需要配置搜索 API 密钥”）。
现在用系统里**已经装好的 Edge/Chrome** 打开结果页，把渲染后的 DOM 抓回来自己解析：

- `HeadlessBrowser`：用 `--headless=new --dump-dom`，**一次调用一个进程**，
  不用 CDP/WebSocket、不占端口、不留常驻进程；找不到浏览器时会如实说明原因；
- 搜索默认走 cn.bing.com（国内能直连），也可以指定 duckduckgo / google / baidu；
  一个引擎一条没解析到就换另一个再试；
- 浏览器不可用/拿不到内容时，退到 HTTP 直取同一个结果页（Bing 是服务端渲染的），
  结果里写明“方式：无头浏览器 msedge.exe”或“HTTP 直取（原因）”，不偷偷换路。

两个真坑（都是实测出来的）：
1. **只读 stdout 不读 stderr 会死锁**：Edge 一启动就往 stderr 写 5KB+ 日志，
   管道写满后浏览器就卡着不退出 —— 表现就是“超时 30 秒被收掉、没吐出内容”。
   现在 stdout/stderr 各开一个线程抽干（stderr 只留一小段做诊断）；
2. PowerShell 里 `& $edge ...` 直接抓输出是空的（浏览器不跟控制台玩），
   得重定向到文件才看得到 DOM —— 晴天验证时差点以为浏览器不能用。

### 108. 修好的工具（用户实测报告的那几个）

| 工具 | 以前 | 现在 |
|---|---|---|
| `git_diff` | 文件路径当位置参数 → git 当 revision 解析（ambiguous argument） | 路径放 `--` 后面，另加 `rev` 参数（如 HEAD~1） |
| `git_remote add` | 必须同时给 name+url | name 可省：没远程就 origin，否则取仓库名；成功后的沉默也给出“已添加 xxx” |
| `git_log` | 空仓库时把 git 的 fatal 当成功吐回去 | “这个仓库还没有任何提交…” / “不是 git 仓库” |
| `git_commit` | 无改动时报错 → 模型反复重试（触发拦截） | “没有需要提交的改动（工作区是干净的）”当成成功 |
| `modify_file` | 只给 content 不给行号 → “行号超出范围: 0” | 支持 `oldText`+`content` 按原文替换；真缺就直说缺什么 |
| `word_count` | 非文本文件直接失败 | 退到按字节数，并说明“不是能解码的文本” |
| `translate` | 占位（“需要配置翻译API密钥”） | 走免费公开接口（MyMemory），长文本自动分段；真翻不动就如实说 |

**顺手修了一个更大的病根**：文本通道的解析器 `QwenToolCallParser`
**只认 `<parameter=名>值</parameter>`**，而模型也经常把参数写成一个 JSON 对象：

```
<tool_call><function=git_log>{"path": "repo", "count": 3}</function></tool_call>
```

这种写法会被当成“没有参数”，工具回一句“缺少必需参数: path”，整轮白白浪费（模型只好重试）。
现在一个 `<parameter>` 都没找到时，会把那块内容当 JSON 读一遍（兼容 ```json 围栏和前面带一句话）。
