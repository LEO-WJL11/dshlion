# 界面说明（配色 / 设置面板 / @ 补全）

## 一句话

界面从"深蓝 + 紫色霓虹"改成**两套中性配色**（黑灰 / 白灰，设置里切换），
设置里能**开关每个插件**、**看/指定技能**，输入框里打 `@` 能**补全文件、历史对话、技能**。
全部逻辑仍在单文件 `web/index.html` 里，没有构建步骤。

改动前，界面里散着 23 个硬编码颜色（`#6c5ce7`、`#16213e`、`#a0a0b8` …）；
现在**一个都不剩**，只有变量定义行里出现颜色值。

---

## 1. 两套配色

主题挂在 `<html data-theme="dark|light">` 上，所有组件样式只用 `var(--x)`，
所以**切换立即生效，不用刷新**，也没有两套重复的组件样式。

不再是霓虹色；紫色强调色 `#6c5ce7` 换成了灰蓝。

### 怎么切换

设置（侧栏 ⚙️ 设置）→ **界面** → 三张卡：

| 选项 | 行为 |
| --- | --- |
| 暗色（黑 + 灰） | 固定暗色 |
| 亮色（白 + 偏灰） | 固定亮色 |
| 跟随系统 | 系统深色就暗色、浅色就亮色（默认选项） |

选择存在 `localStorage['lionbox.theme']`，**刷新后保持**。
没选过时按 `prefers-color-scheme` 自动选；系统配色变了（选了"跟随系统"时）会跟着变。
`<html>` 上先写了 `data-theme="dark"` 作为兜底，脚本一执行就按存档改写，避免刷新时闪一下另一套配色。

## 2. 设置面板

弹窗还是老样子（侧栏「⚙️ 设置」或顶栏模型横幅），里面多了三个页签：

| 页签 | 内容 |
| --- | --- |
| **界面** | 主题三选一 |
| **插件** | 插件列表（按类型分组）+ 开关 + 重新加载 + 开发模式 + 生成骨架 |
| **技能** | 技能列表 + 开关 + 当前会话「指定使用」 |
| 插件管理 | **插件唯一入口**（1.5.2 起）：每类插件的开关 + 该插件自己的参数、技能清单、审批策略、团队成员、自动化任务，全在这一页里 |
| 模型来源 / 音效提醒 / 本地模型 | 原有页签，行为不变 |

侧栏「🧩 插件 / 技能」直接打开设置里的插件页签（老入口保留）。

### 插件页签

- 顶部：**↻ 重新加载插件**（`POST /api/plugins/reload`）、**插件开发模式**开关（`POST /api/plugins/dev-mode`）、当前插件目录。
- 列表按后端给的 `kinds[].label`（中文名）分组；没给过的分类排在后面，用内置默认表（工具 / 技能 / …）。
- 每行：名称 + 说明 + 来源（内置 / 外置）+ 版本 + 右侧开关。
  - 有 `error` 的插件，红字显示原因（`✗ …`）。
  - 来源优先看后端的 `builtin`；老接口没有这个字段时才看 `source` 字符串，
    路径形态的 `source` 算"外置"并把完整路径放进 `title`（鼠标停一下能看到）。
- 开关调 `POST /api/plugins/{id}/enable|disable`：**成功就地更新**（不重画整个面板，滚动位置不丢），
  **失败把开关拨回去**并把原因写在面板上。
- 开发模式打开后出现「生成插件骨架」表单（id / 名称 / 类型 → `POST /api/plugins/scaffold`），
  成功后把生成的路径显示出来，并自动重新加载插件列表。

### 技能页签

- 顶部：**↻ 重新加载技能**（`POST /api/skills/reload`）。
- 「当前会话指定使用」区：已指定的技能显示成**可点 × 移除的标签**，调 `POST /api/skills/active {sessionId, skills}`；
  进页面时用 `GET /api/skills/active?sessionId=` 读回来。
- 每行：名称 + description + 适用场景 + 来源 + 「指定使用 / 取消指定」+ enable/disable 开关。

### 后端没就绪时

`/api/plugins`、`/api/skills` 任何一个拿不到（404 / 500 / 网络错），
对应区块显示 **"该功能的后端还没就绪（GET /api/xxx：…）。聊天、工具调用、模型设置都不受影响。"**，
不会白屏、不会弹错误框。新老两种返回格式都能吃：

| 新契约 | 老格式（兼容） |
| --- | --- |
| `{ok:true, plugins:[…], kinds:[…], devMode}` | `{success:true, data:[{id,name,type,version}]}` |
| `{ok:true, skills:[…]}` | `{success:true, data:[…]}` |
| `{ok:true, items:[{type,label,detail,insert}]}` | `{success:true, data:{items:[…]}}` |

## 3. 输入框 @ 补全

在消息输入框里打 `@`（前面是空格或行首）就会弹候选浮层：

- 请求：`GET /api/context/mentions?q=<@ 后面的词>&kind=all&limit=20&root=<当前工作区>&sessionId=<当前会话>`
  - **防抖 200ms**：连打几个字只发一次；
  - 请求带**序号**，慢的旧响应回来时如果已经有更新的请求，直接丢掉（不会"打完字了列表又跳回去"）。
- 键盘：`↑` `↓` 选择（循环）、`Enter` / `Tab` 确认、`Esc` 关闭。
  浮层开着时 `Enter` 不会把消息发出去；浮层关着时回车照常发送。
- 鼠标：点候选项即选中（用 `mousedown`，不会被输入框失焦抢先）。
- 选中后把 `@词` 替换成后端给的 `insert` 文本（如 `@file:src/main/java/…`、`@history:xxx`、`@skill:pdf`），
  并在输入框上方渲染成**带类型的小标签**（文件 / 历史 / 技能），点标签上的 `×` 就把这条引用从正文里删掉。
  标签是从正文实时解析出来的（正则 `@(file|history|skill):非空白`），所以正文和标签永远一致。
- 端点不存在 / 报错 / 返回为空：浮层**静默不出现**，不弹错误、不挡输入。

## 4. 怎么自测

```powershell
python tools\checks\_check_ui.py
```

35 条断言，分三层：

1. **静态**：两套主题变量都在、变量定义之外没有硬编码颜色、旧配色一个不剩、
   设置面板与浮层 DOM 在、`/api/plugins` `/api/skills` `/api/context/mentions` 都被引用、
   `seenEvents` 去重逻辑与 `pollEvents` / `loadHistory` 的工具行格式没被破坏；
2. **行为**（假 DOM + `node` 真跑）：主题切换与持久化、`@` 防抖/键盘/插入/引用标签/乱序响应/接口挂掉时的降级、
   插件面板分组与开关回滚、技能面板与「指定使用」、以及 404 时显示"后端还没就绪"；
3. **网络**：本地起一个静态服务真 `GET /index.html`，断言 HTTP 200、字节数与文件一致、结尾是 `</html>`。

另外三套老回归也要保持通过：

```powershell
python tools\checks\_check_ui_features.py      # 假 DOM 跑设置页 / 历史渲染 / 下载窗口
python tools\checks\_check_ui_app_methods.py   # App.xxx() 调用都有定义
python tools\checks\_check_ui_api.py           # 前端 fetch 的路径后端都有
```

## 5. 改界面时注意

- **不要写死颜色**：加样式就往 `:root`（暗色）和 `html[data-theme="light"]` 里加变量，
  组件里一律 `var(--x)`；`_check_ui.py` 会扫硬编码颜色（变量定义行不算）。
- 工具调用行必须保持一行一条（`🔧 调用工具：X …` / `✅ X 完成` / `❌ X 失败`），
  `seenEvents` / `seenEventOrder` 的去重逻辑别动 —— 动了会出现重复行。
- 新增的每个 `fetch` 都要有 `.catch`，面板失败只影响自己那一块。
- 页面是由 Maven 在打包时从 `web/` 复制到 `static/` 的（见 `pom.xml` 的 `maven-resources-plugin`），
  所以**改完 `web/index.html` 要重新构建/jar 才会在运行中的实例里生效**；
  跑着的老实例发出去的仍是上次构建时的那份拷贝。
